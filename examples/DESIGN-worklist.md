# DESIGN — 모래 작업함

문서 작성 예시다. 실제 고객/업무 데이터가 없으며 제품 구현·사용자 승인·브라우저 검사 완료를 주장하지 않는다.

## 진단·목표
모드: 신규 설계. 유형: 업무/관리. 사용자는 검토할 작업을 검색하고 상태를 비교하는 담당자다. 데스크톱 키보드와 휴대폰 조회를 지원한다. 참고 초기 코드는 `evals/fixture/`의 원본 HTML/CSS/JS이며 가상 작업 3건과 로컬 메모 폼이 있다. 빌드/외부 의존성은 없다. 실제 백엔드·권한 모델·인증은 범위 밖이다.
기존 갈색/모래색과 system-ui를 유지한다. 한 번에 상태를 비교하는 밀도를 유지하고 장식 hero를 추가하지 않는다. 이 예시는 문서로만 작성하므로 셸·브라우저·이미지 열람 검증은 미수행이다.

## 방향·주 행동
주 행동은 ‘검토할 작업 찾기’, 보조 행동은 ‘메모 작성’이다. 결과 목록은 기존 제목뿐인 데이터를 유지해 목록으로 시작한다. 상태/담당자 필드가 승인되면 비교표로 전환한다. 현재 데이터에 없는 업무 상태나 승인 수치를 만들지 않는다. 불투명 surface를 유지하고 blur는 추가하지 않는다. 이유는 예측 가능한 대비와 작은 변경 비용이다.

## 구조·대표 화면
큰 화면: 브랜드/제목 → 검색 label/입력/지우기 → 결과 수/목록 → 메모 폼. 작은 화면: 같은 DOM 순서, 검색 컨트롤만 공간에 따라 줄바꿈. 제목을 숨기지 않고 모든 결과는 목록에서 읽을 수 있다. 단일 정적 경로라 전역 메뉴/탭은 해당없음. 새로고침하면 검색과 임시 메모가 초기화되는 데모임을 표시한다. 개인정보를 URL에 넣지 않는다.
대표 화면은 작업함 하나다. 검색과 저장 실패 상태를 확인한 뒤에만 상세 화면 확장을 논의한다. 상세/필터/권한은 이번 설계의 구현 승인 범위가 아니다.

| 요구 | 컴포넌트/파일 | 이벤트·상태 | 검사 |
|---|---|---|---|
| 제목 검색 | search + render / app.js | input → 일치 목록/개수 | 일치/불일치/빈 검색 |
| 검색 복구 | 지우기 버튼 / index.html | click → 빈 값/render/입력 focus | 전체 결과와 초점 |
| 메모 실패 설명 | note-form / app.js | submit → 데모 실패, 입력 보존 | 값 유지/재시도 |

## 토큰·시각 체계
style.css의 `--brand:#77402b`, `--paper:#fff8ee`, `--ink:#302b27`, `--space:1rem`을 재사용한다. 새 팔레트는 없다. 본문 1rem/1.6 system-ui, 입력/버튼 padding .65rem, border 1px brand, radius .25rem, main max-width 52rem, 폼 max-width 28rem이다. 기존 heading은 브라우저 기본 크기/굵기를 사용한다. 별도 그림자/z-index는 없다. 포커스는 3px #245ba8, offset 3px. 보조 지우기 버튼은 paper 바탕/brand 글자, 저장은 brand 바탕/흰 글자다. 대비는 미측정이며 최종 확인 전 읽기 적합성을 선언하지 않는다. 다크 테마는 제공하지 않는다.
아이콘과 웹폰트 파일은 쓰지 않는다. 버튼 텍스트가 접근 가능한 이름이다. OS 시스템 폰트 참조만 사용한다.

## 상태·복구
- 정상: 3건 가상 목록, 결과 수 표시.
- 로딩: 해당없음, 동기 로컬 배열 검색이다.
- 빈 결과: ‘검색 결과 없음’, 지우기로 전체 복구.
- 오류: 메모 저장은 고정 데모 실패, 입력 보존·재시도 문구.
- 성공: 검색 결과 갱신은 결과 수로 표현. 실제 저장 성공은 백엔드가 없으므로 해당없음.
- 권한 제한: 인증/서버가 없어 해당없음. 실제 업무 권한을 구현했다고 설명하지 않는다.
- 긴 값: 줄바꿈, 상세 데이터가 없으므로 생략 없이 표시.
hover/active는 기존 브라우저 동작을 유지하고 focus-visible은 명시한다. 검색 지우기는 항상 활성화해 빈 검색에서도 일관된 행동을 제공한다. 파괴적 행동/중복 서버 요청은 없다.

## 반응형·접근성·성능
검색 행은 flex-wrap으로 컨테이너 폭에 반응한다. 검사 목표는 360/768/1280 CSS px와 200% 텍스트 확대이며 Apple 공식 breakpoint가 아니다. 한글 제목은 자연스럽게 줄바꿈한다. Tab 순서는 검색 → 지우기 → 메모 → 저장. 지우기 뒤 검색에 포커스. label과 input id를 연결하고 결과/저장 안내는 role=status를 사용한다. 브라우저/스크린리더에서 실제 안내 빈도는 검증해야 한다.
애니메이션/투명 효과/외부 미디어가 없어 reduced-motion/불투명 fallback 추가는 해당없음. forced-colors의 focus/테두리는 수동 검사 대상이다. 네트워크 0요청을 설계 목표로 두며 성능은 미측정이다.

## 검증·인계
현재 문서 예시는 정적 설계만 제공한다. 실제 명령/브라우저 조작/시각 열람 증거는 없으므로 모두 미검증이다. 구현 담당은 기존 fixture를 읽고 검색·지우기·메모 실패를 구현/검사한다. 브라우저 검토자는 뷰포트별 잘림, Tab/Enter/Space, 포커스 복귀, 상태 낭독, 대비를 확인한다. 실패를 수정하고 같은 시나리오를 다시 실행한다.

## 출처·승인
Apple 위계/가독성 원칙의 자체 해석, 웹 native label/button/status 의미, 프로젝트 브랜드 토큰을 구분한다. HIG 최신성/키트 파일은 조회하지 않았고 Apple 자산도 사용하지 않았다. UI 키트 해시/버전은 해당없음이다. 이 문서는 완성된 **설계 예시**이며 실제 사용자 승인 기록이 아니다. 실제 신규 프로젝트에서는 방향 승인을 받고 구현한다.
