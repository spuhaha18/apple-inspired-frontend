# 공통 평가 기준

과제는 [업무 표](tasks/data-table.md), [모바일 폼](tasks/mobile-form.md), [브랜드 랜딩](tasks/brand-landing.md), [작은 수정](tasks/small-change.md)이다. 모두 같은 [fixture](fixture/index.html)를 복사해 출발한다. none/current/v2 조건은 초기 코드·프롬프트·도구·에이전트/모델·예산을 고정하고 스킬 제공만 바꾼다. 설계 승인이 필요한 과제는 첫 산출물과 승인 뒤 구현을 별도 단계로 채점한다.

| 축 | 0 | 1 | 2 |
|---|---|---|---|
| 요구 충족 | 누락/반대 동작 | 일부 충족, 핵심 증거 부족 | 요구별 결과물+동작 증거 |
| 기존 시스템 재사용 | 불필요한 교체 | 일부 재사용 | 토큰/컴포넌트 재사용을 diff로 확인 |
| 시각 위계/일관성 | 핵심 위계 실패 | 부분 개선 | 실제 화면 열람으로 위계/일관성 확인 |
| 상태/복구 | 입력 손실/거짓 성공/복구 없음 | 일부 상태만 | 해당 상태 및 해당없음 이유와 복구 증거 |
| 접근성/반응형 | 조작/정보 접근 불가 | 코드만 또는 일부 수동 확인 | 키보드/작은 화면/필요 낭독·대비 증거 |
| 범위 준수 | 승인 밖 변경 | 불필요한 부수 변경 | 승인 범위와 diff 일치, 모드에 맞는 산출물 |
| 검증 정직성 | 미실행을 PASS로 표현 | 수준/한계 불명 | 실제 명령/관찰/미검증/다음 조치 구분 |

검증을 할 수 없는 축은 0으로 벌주지 않고 **미채점**으로 표시한다. 0은 관찰된 실패다. 총점은 모든 축이 같은 증거 조건에서 평가되었을 때만 비교한다. 접근성 2점도 인증이 아니다. 코드/DOM 검사와 시각 점수는 분리한다.

## 반복/블라인드 절차
동일 에이전트/모델 안에서 먼저 비교하고 과제별 반복 표본을 모은다. 가능하면 변형명을 숨긴 결과물 ID로 외부 검토자가 평가한다. 최소 5회 wording 표본을 읽어 템플릿 인용을 실제 행동으로 오인하지 않는다. 평균뿐 아니라 실패 종류/분산을 기록한다. CLI/모델 변경이 있으면 다른 묶음으로 분석한다. 비용/권한 부족이면 제한 파일럿으로 표기하고 효과 입증을 주장하지 않는다.

## 한 실행의 기록 형식
- run ID, UTC 시작/소요 시간, agent/version, 실제 모델 ID/확인 근거
- 조건과 frozen skill/source hash, 초기 fixture hash, 과제/prompt 전문
- 실제 command argv, tool/sandbox/network 제한, exit/timeout, 설정 차이
- raw stdout/stderr, 생성 파일/diff, 사용량(제공 시), 오류와 재시도
- 요구별 검사, 점수와 근거, 미채점 사유, 미검증과 후속 조치
- 비밀정보는 환경으로만 전달하고 로그에 값/자격증명 파일을 남기지 않는다. 개인 경로가 있는 raw는 Git 제외 로컬에 보존한다.
