# 조건별 UI 판단

아래는 스킬 자체의 웹 판단 규칙이다. Apple 공식 치수나 모든 제품에 강제되는 구조가 아니다. 기존 프로젝트 결정이 있으면 그 근거를 먼저 확인한다.

| 관찰 가능한 조건 | 선택 | 이유 | 예외/전환 조건 |
|---|---|---|---|
| 기존 브랜드/토큰이 구현되어 있다 | 기존 의미 토큰과 컴포넌트를 재사용 | 일관성과 변경 범위 유지 | 대비/상태 구분 실패가 측정되면 영향 토큰 개선안을 합의 |
| 승인된 한 요소의 동작만 바뀐다 | 작은 변경 + CHANGE | 전체 설계보다 검증/인계에 집중 | 탐색/브랜드/핵심 동작이 바뀌면 기존 개선으로 재분류 |
| 행 사이 수치/상태 비교가 핵심이다 | 의미 있는 헤더의 표 | 같은 축에서 빠르게 비교 | 개별 이미지 탐색이 핵심이면 카드, 단순 순서는 목록 |
| URL 공유/새로고침/back 복원이 필요하다 | 경로/쿼리로 탐색·필터 상태 표현 | 웹 기대 동작 보존 | 비공개 입력은 URL에 넣지 않고 세션 내 상태 사용 |
| 화면 안의 동등한 보기만 전환한다 | 탭 또는 명시적인 보기 선택 | 전역 탐색과 구분 | 실제 다른 목적지는 링크로 탐색 |
| 결과가 비었다 | 최초 데이터 없음과 필터 결과 없음 분리 | 추가/필터 초기화 중 맞는 복구 제공 | 권한으로 비어 보이면 권한 안내로 구분 |
| 서버 저장/구매/제출이다 | 응답 확인 후 성공, 실패 시 입력 유지 | 데이터 손실/거짓 성공 방지 | 검증된 낙관적 UI 정책이 있으면 취소/롤백과 최종 상태 표시 |
| 파괴적/비가역 작업이다 | 대상/결과가 구체적인 확인과 분리된 위험 버튼 | 실수 비용 감소 | 안전한 undo가 있으면 확인 대신 복구 가능 시간을 명시 |
| 좁은 화면에서 열이 넘친다 | 핵심 필드 우선 + 상세 접근 또는 표 스크롤 | 중요 정보 유지 | 비교가 핵심이면 카드 강제 변환보다 이름 붙인 스크롤 영역 |
| 움직임이 정보 전달에 필요하지 않다 | 정적 상태, reduced-motion에서 제거 | 읽기와 멀미 부담 감소 | 진행 변화 자체가 정보면 텍스트 상태도 함께 유지 |
| 투명 표면에서 대비가 흔들린다 | 불투명 surface | 배경에 무관한 읽기 | 제한된 탐색층 효과는 대비/성능 측정과 fallback을 전제로 합의 |
| 브라우저/이미지 열람 도구가 없다 | 정적/실행 검사와 시각 미검증을 분리 | 증거 범위를 정확히 전달 | 후속 검토자가 실제 화면을 보면 그 항목만 갱신 |

결정 기록은 `조건(관찰 파일/상태) → 선택 → 사용자 작업상의 이유 → 예외 적용 여부 → 검증` 한 묶음으로 쓴다. “Apple답게”처럼 검증 불가능한 표현 대신 어느 위계와 행동이 명료해지는지 적는다.
