# 탐색 패턴

## 사용 조건
화면/경로 이동, 같은 화면의 보기 전환, 메뉴·탭·현재 위치를 설계하거나 고칠 때 읽는다.

## 선택 규칙과 예외
- 서로 다른 목적지이면 링크와 실제 URL을 쓴다. 새로고침/북마크/back이 같은 목적지를 재현해야 한다.
- 같은 맥락의 동등한 패널 전환이면 탭을 검토한다. 탭으로 채택하면 선택 상태·패널 연결·방향키 이동을 함께 구현한다. 단순 링크 메뉴를 role=tab으로 꾸미지 않는다.
- 주요 영역이 많고 반복 이동이 핵심이면 기존 사이드바를 유지한다. 영역이 적으면 상단 탐색을 우선 검토한다. 예외: 브랜드형 사이트는 문서 앵커만으로 충분할 수 있다.
- 현재 위치는 색 외 텍스트/형태와 `aria-current`로 표시한다. 버튼은 행동, 링크는 이동이라는 웹 의미를 유지한다.

## 구성 요소
서비스/영역 이름, 주요 목적지, 현재 위치, 페이지 제목, 주 행동, 필요할 때 뒤로/상위 경로. breadcrumb는 실제 계층이 있을 때 쓴다. 주 행동을 탐색 메뉴 속에 숨기지 않는다.

## 상태
기본/현재/hover/focus, 페이지 로딩, 없는 경로, 권한 없음, 연결 실패를 구분한다. 권한 없음은 빈 페이지가 아니라 접근 가능한 안내와 안전한 돌아갈 경로를 제공한다. 데이터 loading에서도 현재 제목/탐색 맥락을 유지한다. 전환 성공은 페이지 제목·내용으로 드러나며 중복 성공 토스트는 필요 없을 수 있다.

## 작은 화면
사이드바가 본문을 밀어내면 메뉴 버튼으로 접고 접근 가능한 이름/열림 상태를 둔다. 접힌 메뉴 안의 목적지가 사라져서는 안 된다. 모달형 메뉴이면 배경 상호작용 제한, Escape 닫기, 트리거로 포커스 복귀를 구현한다. 비모달 확장 목록에는 불필요한 포커스 가두기를 적용하지 않는다.

## 키보드/접근성
건너뛰기 링크, landmark, 보이는 포커스, 논리적인 DOM 순서를 유지한다. 링크는 Enter, 버튼은 Enter/Space로 동작한다. SPA 전환이면 제목/초점과 낭독 안내 정책을 정한다. WAI-ARIA 패턴은 해당 위젯을 채택했을 때만 적용한다.

## 좋은 예 / 나쁜 예
- 좋은 예: ‘문서’ 링크를 열면 `/documents?q=계획`이 재현되고 상세에서 back을 누르면 검색 맥락으로 돌아온다. 토큰/주소에 개인 입력이 포함되는지는 별도 확인한다.
- 나쁜 예: 클릭 가능한 div마다 화면만 바꾸고 URL과 포커스는 그대로 둔다. 현재 메뉴는 파란색으로만 구분한다.

## 검증 방법
직접 URL → 새로고침 → 상세 → back을 실제 수행한다. 키보드만으로 모든 목적지를 열고 현재 위치/메뉴 닫힘/포커스 복귀를 확인한다. 작은 화면 메뉴가 열린 상태/닫힌 상태를 각각 캡처하고 열람한다. 실행하지 못하면 정적 링크 검사와 미검증으로 분리한다.

## 출처 구분
