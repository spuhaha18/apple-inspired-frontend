# 시각 체계 패턴

## 사용 조건
정보 위계, 타이포그래피, 간격, 색/표면, 아이콘, 모션을 결정하거나 일관성을 수정할 때 읽는다.

## 선택 규칙과 예외
- 기존 브랜드가 있으면 의미 토큰/서체/밀도를 재사용한다. 흰색 카드와 회색으로 일괄 교체하지 않는다.
- 주 행동과 제목을 먼저 식별하고 보조 정보의 크기/굵기/간격을 상대적으로 낮춘다. 모든 영역을 같은 카드/그림자로 강조하지 않는다.
- 관련 요소 내부 간격은 그룹 사이보다 좁게 해 관계를 만든다. 고정 픽셀보다 프로젝트 간격 토큰을 우선한다.
- 콘텐츠는 불투명 표면을 기본으로 한다. 예외: 탐색층의 효과가 합의되었으면 blur의 대비/성능과 불투명 fallback을 함께 확인한다.
- 상태색은 텍스트/아이콘/형태를 동반한다. 아이콘은 의미·이름·라이선스 확인 후 기존 세트로 선택한다.
- 모션은 원인/변화의 관계를 보여줄 때 쓴다. reduced-motion에서는 비필수 이동을 제거하고 상태 텍스트를 유지한다.

## 구성 요소
의미 토큰 background/surface/text/muted/border/accent/danger/success/focus, 제목/본문/보조 타입 단계, 간격·반경·그림자, 아이콘 크기/선/기준선, focus-visible, z-index 정책. 새 토큰은 기존 값과 역할이 다른 경우에만 추가한다. 출발값이 필요하면 [웹 적용](../web-adaptation.md)의 자체 제안을 검토한다.

## 상태
hover/focus/active/disabled, 선택, 로딩, 빈 상태, 오류, 성공, 권한 제한에서 위계와 읽기를 유지한다. 비활성 텍스트와 단순 보조 텍스트의 의미를 구분한다. 라이트/다크를 제공하는 프로젝트이면 상태별 조합을 각각 측정한다. 다크 모드를 요청 없이 추가하지 않는다.

## 작은 화면
제목이 여러 줄이 되어도 CTA를 밀어 숨기지 않는지 확인한다. 한글 어절/긴 URL/숫자의 줄바꿈을 검토하고 필요한 경우 overflow-wrap을 사용한다. 정보 밀도는 사용자 작업에 맞게 조정하되 숨기는 정보에는 접근 경로를 둔다. 텍스트 확대에서도 고정 높이가 내용을 자르지 않게 한다.

## 키보드/접근성
색 대비는 실제 foreground/background 조합으로 도구 측정한다. focus-visible이 hover보다 덜 보이지 않게 하고 forced-colors에서도 의미를 유지한다. 장식 아이콘은 낭독 대상에서 제외하고 동작 아이콘에는 접근 가능한 이름을 둔다. CSS px 목표와 Apple native pt, WCAG 기준을 같은 수치 규칙으로 취급하지 않는다.

## 좋은 예 / 나쁜 예
- 좋은 예: 모래색 브랜드의 갈색 액션을 유지하며 검색 지우기를 보조 테두리 버튼으로 표현한다. 측정 전에는 대비를 ‘미측정’으로 적는다.
- 나쁜 예: 모든 패널에 blur와 반짝임을 넣고 SF 폰트를 복사한 뒤 ‘Apple 공식 웹 수치’라고 설명한다.

## 검증 방법
긴 제목/빈 상태/오류/로딩 캡처를 실제 열람한다. 확대/좁은 화면/다크·고대비(제공 시)/reduced-motion을 확인한다. 대비 도구와 입력값·결과, 성능 측정 환경을 남긴다. 캡처 생성만으로 검토를 완료하지 않는다.

## 출처 구분
Apple 원칙과 웹 자체 시작값의 구분은 [웹 적용](../web-adaptation.md), 자산 경계는 [UI 키트](../ui-kits-and-symbols.md)를 따른다. 웹 기준: [WCAG 2.2](https://www.w3.org/TR/WCAG22/). 그룹 간격/토큰 재사용/강조 방식은 스킬 자체 제안이다.
