# 데이터 표시·검색·필터 패턴

## 사용 조건
데이터 묶음을 탐색/비교/선택하고 검색·정렬·필터·페이지를 조작하는 화면에 적용한다.

## 선택 규칙과 예외
- 같은 필드를 행 사이에서 비교하면 표, 제목을 순서대로 읽으면 목록, 개별 이미지/콘텐츠를 탐색하면 카드를 선택한다.
- 데이터가 적고 로컬이면 즉시 필터를 쓸 수 있다. 서버 검색이면 제출/지연 정책과 오래된 응답 무시 정책을 명세한다. 검색어는 결과와 함께 유지한다.
- 필터가 적용되면 선택값과 결과 수, 초기화 경로를 보여준다. 검색 지우기 버튼이면 검색만 지울지 다른 필터까지 지울지 이름/동작으로 구분한다.
- 정렬은 명시적인 헤더 버튼과 상태 표시를 둔다. 페이지가 있는 결과에서 검색/필터가 바뀌면 첫 페이지로 돌리고 범위·개수를 갱신한다.
- 예외: 실시간 스트림은 페이지보다 새 항목 알림/일시정지가 유용하다. 비교표는 좁다고 반드시 카드로 바꾸지 않는다.

## 구성 요소
결과 제목, 검색 label, 필터, 정렬, 결과 수/적용 조건, 표 헤더/행 또는 목록, 빈 상태, 페이지 제어, 상세 링크. 행 선택과 상세 이동의 클릭 영역/키보드 동작을 분리한다. 대량 작업이면 현재 페이지/전체 결과 중 선택 범위를 표시한다.

## 상태
정상, 최초 데이터 없음(추가 행동), 필터 결과 없음(조건 초기화), 로딩(이전 결과와 최신성 표시), 서버 오류(조건 유지·재시도), 성공(갱신된 개수), 권한 제한(열/행/행동의 접근 정책), 긴 값/부분 누락을 정의한다. 실패 결과를 0건으로 위장하지 않는다. 새 검색 성공 전에 낡은 응답이 목록을 덮지 않게 한다.

## 작은 화면
핵심 필드를 유지하고 축약 필드는 상세에서 접근하게 한다. 수평 스크롤이면 영역의 목적과 스크롤 가능성을 전달한다. 잘리는 긴 값은 펼치기/상세로 전체 확인 경로를 둔다. 좁은 화면에서도 검색 초기화와 결과 개수가 보이도록 줄바꿈한다.

## 키보드/접근성
일반 표는 table/caption/th와 필요한 scope를 사용한다. 단순 표에 grid 키보드 모델을 덧붙이지 않는다. 정렬 상태를 `aria-sort`로, 결과 갱신을 절제된 상태 영역으로 알린다. 필터 초기화 뒤 포커스 정책은 검색 입력 또는 호출 버튼 중 실제 작업 맥락에 맞게 정한다. 모든 아이콘 버튼에 이름을 둔다.

## 좋은 예 / 나쁜 예
- 좋은 예: ‘제목 검색’을 지우면 조건이 비고 전체 목록/결과 수가 갱신되며 입력에 포커스가 돌아온다. 상태 필터는 명세대로 유지된다.
- 나쁜 예: 결과 없음에 ‘문서가 없습니다’만 표시해 필터를 지울 길이 없고, 휴대폰에서는 상태 열을 영구 숨긴다.

## 검증 방법
고정 가상 데이터로 전체 → 일치 → 불일치 → 지우기 → 재검색을 실행한다. 정렬/페이지/필터 조합과 서버 지연/실패를 재현한다. 헤더 관계, 키보드 순서, 긴 값/작은 화면/확대를 확인한다. 코드 검사는 브라우저 재현 및 시각 열람과 별도 기록한다.
