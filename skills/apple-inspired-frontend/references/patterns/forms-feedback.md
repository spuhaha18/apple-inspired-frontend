# 폼·저장·피드백 패턴

## 사용 조건
입력, 검증, 서버 저장/제출, 알림, 취소/삭제와 복구 동작에 적용한다.

## 선택 규칙과 예외
- 사용자가 입력하는 값에는 항상 label을 제공한다. placeholder는 예시이지 이름의 대체가 아니다.
- 입력 형식은 클라이언트에서 안내하고 권한/중복/충돌 등 서버 판정은 서버 오류로 구분한다. 입력 도중 매 키마다 공격적인 오류를 띄우지 않고 제출 또는 적절한 이탈 시점에 안내한다.
- 서버 응답이 필요한 저장이면 응답 확인 뒤 성공을 표시한다. 실패 시 입력과 선택을 유지하고 재시도 경로를 둔다.
- 비가역 삭제면 대상·결과가 명확한 확인을 둔다. 예외: 검증된 undo 흐름이면 복구 기한/범위와 실패 처리를 제공한다.
- 낙관적 저장은 기존 제품 정책이 있을 때만 사용하고 임시/확정 상태와 rollback을 구분한다. 사용자 요청 없이 결제/서명 완료를 자동화하지 않는다.

## 구성 요소
제목/설명, 논리적 fieldset/legend, label/도움말, 입력, 필드별 오류, 필요시 오류 요약, 주 제출 버튼, 취소/돌아가기, 저장 상태, 위험 행동. 별표만으로 필수/선택을 구분하지 않는다. 버튼은 ‘확인’보다 ‘예약 요청’처럼 결과를 드러낸다.

## 상태
기본/편집/유효하지 않음/제출 중/성공/서버 실패/권한 만료/변경 충돌을 정의한다. 제출 중 중복 요청을 막되 진행 상태와 취소 정책을 알려준다. 빈 입력과 빈 데이터 화면을 구분한다. 성공 후 이동/초기화/입력 유지 중 정책을 정한다. 통신 실패는 성공 토스트와 동시에 나타나지 않는다.

## 작은 화면
label은 입력과 가깝게 놓고 넓은 다열 폼은 읽는 순서대로 한 열로 줄인다. 키보드가 열린 상태의 오류/제출 버튼 가림을 확인한다. 고정 하단 CTA가 있으면 콘텐츠와 포커스가 가려지지 않게 여유를 둔다. 적절한 input type/autocomplete를 검토한다.

## 키보드/접근성
native 입력/버튼을 우선하고 `aria-invalid`/`aria-describedby`로 오류를 연결한다. 제출 오류 후 첫 오류나 오류 요약으로 초점을 이동하는 정책을 정한다. 서버 상태는 과도한 반복 없이 알린다. 모달 확인은 제목/설명, Escape, 초기 초점, 종료 후 트리거 복귀를 갖춘다. 위험 기본값 대신 안전한 취소를 고려한다.

## 좋은 예 / 나쁜 예
- 좋은 예: 저장 실패 문구 아래 ‘다시 저장’이 있고 작성한 메모가 그대로 남는다. 필드 오류와 서버 장애 메시지의 위치가 다르다.
- 나쁜 예: 클릭 즉시 ‘저장됨’ 표시 후 실패하면 입력을 지우고 빨간 테두리만 남긴다.

## 검증 방법
빈 값·잘못된 값·긴 한글·연속 제출·서버 실패·권한 만료·재시도를 테스트한다. 입력 보존과 성공 시점, 버튼 중복 방지, 오류 읽기/포커스를 실제 확인한다. 브라우저가 없으면 이벤트/오류 분기를 코드로 확인하고 키보드/낭독/레이아웃은 미검증으로 기록한다.
