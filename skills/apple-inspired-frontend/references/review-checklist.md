# 검증 체크리스트와 완료 판정

각 항목은 `PASS / FAIL / 미검증 / 해당없음(사유)` 중 하나다. PASS에는 재현 방법과 관찰 증거가 필요하다. 정적 코드 검토 PASS는 브라우저 검증 PASS로 승격되지 않는다.

| 확인 영역 | 실제 확인 방법 | 실패 시 조치 |
|---|---|---|
| 범위/명세 | 요구와 diff를 대조, 승인 근거·유지 토큰 확인 | 무관 변경 제거 또는 범위 재합의 |
| 동작/상태 | 정상·로딩·빈 결과·오류·성공·권한 제한·긴 값 실행 | 상태별 복구/중복 방지 수정 후 재실행 |
| 회귀 | 프로젝트의 관련 테스트/빌드와 기존 핵심 흐름 실행 | 실패 원인을 분리하고 인접 영향도 재확인 |
| 탐색 | 직접 URL/새로고침/back, 선택/필터 복원 | 링크/라우트/상태 보존 수정 |
| 키보드 | Tab/Shift+Tab/Enter/Space, 해당 위젯 키, Escape/포커스 복귀 | native 요소 우선, 읽기/포커스 순서 수정 |
| 의미/낭독 | label·이름·헤더·오류 연결 코드 확인 + 실제 스크린리더 | 두 검증을 나눠 보고, 이름/관계 수정 |
| 대비/색 | 실제 토큰 조합을 계산 도구로 측정, 색 외 텍스트/아이콘 확인 | 의미 토큰 개선, 상태 구분 재검증 |
| 반응형 | 작은/큰 화면, 200% 텍스트, 리플로우/긴 한글/overflow 확인 | 정보 접근 경로와 컨테이너 조정 |
| 모션/효과 | reduced-motion, forced-colors, 불투명 fallback | 비필수 효과 축소; 기능/포커스 유지 |
| 성능 | 실제 기기/브라우저/측정 조건과 결과 기록 | 큰 이미지/blur/animation 영향 최소화 |
| 시각 | 상태·뷰포트가 기록된 캡처를 사람/이미지 열람 도구로 검토 | 잘림/위계/밀도 수정 후 다시 캡처/열람 |
| 자산/규제 | 사용 자산 출처·라이선스, 해당 업무의 별도 권한/감사 요구 | 권한 불명 자산 보류; 전문 검토로 분리 |

## 증거 기록
`항목 / 검사 수준(정적·실행·브라우저·이미지 열람) / 명령 또는 조작 / 기대 / 관찰 / 상태 / 증거 위치`를 적는다. 캡처 파일만 있고 열람하지 않았다면 시각 평가는 미검증이다. 자동 접근성 검사 통과는 WCAG 전체 적합성 선언이 아니다.

## 완료와 중단
요구 범위 구현, 실행 가능한 관련 검사, 실패 수정/재검증, 남은 문제 인계가 있어야 작업 단계를 마친다. 환경이 막혀 중요한 동작을 실행하지 못하면 제한된 완료/차단으로 보고한다. 검증 대기 항목마다 필요한 역량과 다음 조치를 정한다. 검증 실패를 감추기 위한 범위 확장이나 전면 재설계는 하지 않는다.
