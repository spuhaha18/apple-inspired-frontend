# 도구 역량별 실행 경로

시작할 때 실제 제공된 도구와 권한을 확인한다. 특정 제품, MCP, 브라우저 설치가 이 스킬의 전제는 아니다. 사용 가능 여부는 실행 결과와 구분한다.

| 역량 | 수행하는 작업 | 남기는 한계/대안 |
|---|---|---|
| 파일 읽기만 | 관련 코드/명세 분석, 모드 선택, 문서 초안/리뷰 | 파일 저장·실행·시각 검증 미수행; 응답에 문서 내용 인계 |
| 파일 편집 가능 | 승인 범위 코드/명세 수정, 변경 diff 검토 | 실제 실행이 없으면 정적 검토라고 표시 |
| 셸 실행 가능 | 기존 스크립트/관련 테스트/빌드, 필요하면 프로젝트의 로컬 서버 | 명령/작업 경로/종료코드/결과 기록. 의존성 설치는 별도 범위 확인 |
| 브라우저 조작 가능 | 실제 사용자 흐름, 키보드, 뷰포트/확대, 오류/재시도 | DOM 검사와 실제 이미지 검토는 별도 항목 |
| 캡처 생성만 가능 | 뷰포트/상태가 명확한 이미지 파일 생성 | 캡처 존재는 시각 검토가 아님. 열람 가능한 검토자에게 인계 |
| 이미지 열람 가능 | 실제 캡처를 보고 위계/밀도/겹침/잘림 검토 | 이미지로 동작·스크린리더·실제 성능을 증명할 수 없음 |
| 외부 조회 불가 | 패키지 내부의 실행/판단 규칙으로 진행 | 최신 정책/자산 이용 조건은 확인 안 됨. 권한 불명 자산은 사용 보류 |

브라우저 없이도 코드를 수정할 수 있지만 ‘화면 검증 완료’ 대신 `코드 변경 완료; 화면 검증 대기`로 인계한다. 런타임이 없으면 허구의 테스트 명령 결과를 쓰지 말고 정적 검사 근거 파일을 적는다. 도구를 추가 설치하거나 보안 제한을 우회해 가용성을 만드는 것은 자동 후속 작업이 아니다.

계산/대비/성능 측정은 실행한 도구, 입력값/환경, 출력값을 함께 기록한다. 실행 도구가 없으면 ‘미측정’으로 둔다. 예상 결과와 관찰 결과는 다른 열에 쓴다.
