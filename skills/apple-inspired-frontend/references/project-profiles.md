# 프로젝트 유형별 추가 판단

모드와 유형은 별개다. 작은 변경도 업무형일 수 있고 신규 설계도 브랜드형일 수 있다. 복합 서비스는 화면의 핵심 작업을 기준으로 주 유형 하나와 보조 유형을 기록한다. 아래 구조는 자체 권장안이지 Apple 고정 레이아웃 규정이 아니다.

## 업무/관리
- 조건: 반복 처리, 행 비교, 상태 추적, 권한별 행동이 핵심.
- 선택: 비교 가능한 밀도, 명확한 표 헤더/정렬/필터, 현재 결과 범위, 상세로 돌아왔을 때 맥락 복원.
- 구성: 작업 제목/주 행동 → 검색/필터 → 결과/선택 작업 → 페이지/개수. 반복 작업에서 긴 소개 hero를 기본으로 넣지 않는다.
- 추가 상태: 부분 권한, 동시 수정, 오래된 데이터, 대량 작업 일부 실패. 저장/제출/승인/서명은 다른 동작이다.
- 예외: 차트 중심 모니터링은 요약+드릴다운이 우선. 표만으로 고정하지 않는다.
- 확인: 긴 한글/숫자 정렬, 필터 복원, 페이지 이동 후 선택 정책, 위험 작업 재확인. 규제 적합성/감사추적은 별도 검증.

## 일반 서비스
- 조건: 가입, 예약, 설정 등 하나의 사용자 여정을 완수한다.
- 선택: 한 화면의 주 행동을 명확히 하고 단계 간 입력 보존/뒤로 가기 정책을 정한다.
- 구성: 현재 단계/맥락 → 입력/선택 → 결과/다음 행동. 긴 과정을 불필요하게 한 화면에 압축하지 않는다.
- 추가 상태: 재방문, 세션 만료, 중복 제출, 취소/복구. 개인정보는 URL로 노출하지 않는다.
- 예외: 숙련자의 빠른 편집은 불필요한 wizard 대신 같은 화면 편집.
- 확인: 키보드 완료, 오류 뒤 재시도, 로딩 중 중복 클릭, 작은 화면 폼.

## 콘텐츠/커머스
- 조건: 읽기/탐색/비교와 콘텐츠 또는 상품 선택이 핵심.
- 선택: 읽기 폭·제목 위계 또는 이미지/가격/옵션의 비교 기준을 정한다. 이미지 비율과 대체 텍스트를 정의한다.
- 구성: 탐색/검색 → 결과 → 상세 → 관련 행동. 총 가격·배송/재고·반품 조건은 결정 전에 노출한다.
- 추가 상태: 이미지 실패, 품절/가격 변경, 검색 결과 없음, 장바구니 충돌, 결제 대기/실패.
- 예외: 정보 비교가 우선인 상품은 카드 외 비교표도 제공. 읽기 페이지에 구매 CTA를 무조건 고정하지 않는다.
- 확인: 긴 제목/번역, 이미지 없는 경우, 가격 통화/단위, 구매 확정 경계. 실제 결제는 별도 사용자 승인.

## 마케팅/브랜드
- 조건: 이해·신뢰·전환을 만드는 공개 소개 페이지.
- 선택: 기존 목소리/색/서체를 유지하며 주장 → 근거 → 행동의 흐름을 만든다. 모든 섹션에 동등한 CTA를 반복하지 않는다.
- 구성: 핵심 가치와 CTA → 실제 근거/기능 → 질문/조건 → 다음 행동. 가상의 수치·후기·로고를 진짜 근거로 쓰지 않는다.
- 추가 상태: 이미지/영상 실패, 폼 제출 대기/실패, 앵커 이동, reduced-motion.
- 예외: 브랜드가 강한 장식/대형 타이포를 요구하면 읽기·성능·작은 화면을 검증하면서 유지한다. 흰 카드와 회색으로 평준화하지 않는다.
- 확인: 첫 화면의 메시지/행동, 장문 읽기, 레이아웃 이동, 미디어 예산. Apple 브랜드를 복제하는 것과 원칙을 참고하는 것을 구분한다.
